**Section 1: Project Overview** 

**Project title** 

**Library Management System** 

## **Business idea** 

The Library Management System stores information about library members, books, and loans. It helps a library keep track of its collection and record which members borrow which books. 

## **Problem statement and purpose** 

Recording books and borrowing activity manually can lead to duplicated information, missing records, and difficulty finding who borrowed a book. This database organizes the information into related tables so staff can retrieve records, view borrowing activity, update information, and maintain consistent relationships. 

## **Scope** 

The database covers: 

- Registering library members. 

- Storing book details and availability. 

- Recording book loans. 

- Retrieving and sorting member and book data. 

- Combining related records using SQL JOINs. 

- Updating records and changing table structures. 

- Inserting additional members, books, and loans. 

This small practical database does not implement a complete library application, user login, online reservations, payment processing, or automated overdue notifications.

## **Columns and data types** 

## **members** 

- member_id: INTEGER GENERATED ALWAYS AS IDENTITY, primary key. 

- full_name: VARCHAR(100), required. 

- email: VARCHAR(100), required and unique. 

- phone: VARCHAR(20), optional initially; its type is changed in Q4.2. 

## **books** 

- book_id: INTEGER GENERATED ALWAYS AS IDENTITY, primary key. 

- title: VARCHAR(150), required. 

- author: VARCHAR(100), required. 

- category: VARCHAR(50), optional initially; renamed in Q4.1. 

- available: BOOLEAN, required, default TRUE. 

- isbn: added in Q4.3. 

## **loans** 

- loan_id: INTEGER GENERATED ALWAYS AS IDENTITY, primary key. 

- member_id: INTEGER, required foreign key to members.member_id. 

- book_id: INTEGER, required foreign key to books.book_id. 

- loan_date: DATE, required, defaults to the current date. 

- return_date: DATE, optional until the book is returned. 

## **Relationships and keys** 

- One member can have many loan records: members 1-to-many loans. 

- 

- 

- 

   - One book can appear in many loan records over time: books 1-to-many loans. 

   - Each loan refers to one existing member and one existing book. 

   - The identity primary keys uniquely identify records and are generated by PostgreSQL. 

- The foreign keys prevent a loan from referencing a member or book that does not exist.
